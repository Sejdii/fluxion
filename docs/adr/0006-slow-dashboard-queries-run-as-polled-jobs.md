# Slow dashboard queries run as polled jobs

The dashboard starts each query as an in-memory job and polls it, so that a repository that stays slower than a gateway timeout even with the per-month fetch still loads. A query that finishes within a second is answered by the start request, so small repositories behave as before. We rejected streaming and server-sent events because a long-lived response is exactly what a gateway cuts off. Jobs live in the server process: a restart loses them, only the newest 20 uncollected results are kept, and cancelling in the browser does not stop the fetch, because its months are shared through the cache with any other query that needs them. `GET /api/pr` still answers in one request. The pull request port reports each fetched month so that progress counts a month once every repository has it.
