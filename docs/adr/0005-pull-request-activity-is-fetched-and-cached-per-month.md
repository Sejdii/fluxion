# Pull request activity is fetched and cached per month

The caching pull-request source fetches whole UTC calendar months, up to three at once, caches each month per repository and slices the result to the requested range by merge date. A month that had ended when it was fetched is reused by any later range that touches it, however the range moves. A month that had not ended is refetched after 30 minutes, and Refresh clears everything. We rejected one request per range because a year of a busy repository took about 70 s in sequential pages, past a typical gateway timeout, and because GitHub search returns at most 1000 results per query, a limit that now applies per month instead of per range. We rejected caching the range-clipped edge months because their cache key changes whenever the range moves, so the edge months would be refetched on every shift. The cost is that a short range still fetches its whole month. The dashboard and ADR-0002 are unchanged. The port gains `countMergedPullRequests`, a one-search probe of how many merged PRs a range holds; the caching source passes it straight through, uncached, because it is cheap and a stale count would hide growth.
