# Review durations can be measured in working time, as an optional work schedule

Review waiting time and total review time can be measured in working time: only the hours inside an optional work schedule (weekdays, daily hours and a time zone) count. The core applies the schedule to the activity records after they are fetched, so the ports and the cache do not change. Without a schedule, the durations stay wall-clock time, so 24/7 projects see no change. We rejected making working time the only behaviour because open-source projects work around the clock, and a Friday-evening PR reviewed on Monday looks slow in wall-clock time only for teams that do not work weekends. We also rejected one schedule per repository: a single dashboard-wide schedule keeps pooled repositories comparable. Periods stay UTC buckets, tracked separately in #57.
